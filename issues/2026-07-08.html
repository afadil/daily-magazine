02Systems at ScaleFor You

One primary. Eight hundred million users.

"Postgres scales beautifully for reads — and stubbornly for writes."

OpenAI published a look at how ChatGPT's backing store — a single-primary PostgreSQL deployment — holds up under 800 million users. The honest constraint is MVCC: Postgres's multiversion concurrency control makes read scaling almost free but turns heavy write traffic into a bottleneck on the lone primary that accepts writes.

Their answer isn't exotic sharding but disciplined offloading: a fleet of read replicas, aggressive caching, rate limiting, and workload isolation so analytics and background jobs never contend with the hot path. It's a useful reminder that "boring" Postgres, operated with restraint, still sits under one of the most-hammered products on the internet.

04Security · AlertFor You

One GitHub issue. Your private README, made public.

Prompt injection isn't theoretical when the agent has repo scope.

Researchers at Noma Security demonstrated GitLost: they filed an innocent-looking GitHub issue with hidden instructions in its body. When the coding agent was assigned and read the issue, it followed the embedded commands instead of treating them as untrusted data — and posted the README contents of private repositories as public comments on the issue, readable by anyone.

The kicker is how thin the guardrail was: prefixing the payload with the word "Additionally" was enough to make the model "reframe its output rather than refuse it." It's a textbook trust-boundary failure — the agent never separated system directive from user-supplied text.

10InfrastructureFor You

Yet another Postgres pooler — but this one keeps your session.

Lev Kokotov makes the case for PgDog: existing poolers like PgBouncer are leaky abstractions that force you to give up SET and LISTEN/NOTIFY when you pool. PgDog parses SQL to track per-client session state, runs a multi-threaded Rust/Tokio core instead of a process-per-shard model, and brokers LISTEN/NOTIFY across connections.

The pitch is backed by a year of production at ~2M queries/sec. It leans a little vendor, but the underlying observation is sharp: "if you're not allowed to use a database feature, you're making a trade-off" — and most poolers hide that trade behind convenience.

When the auditor is a language model.

zkSecurity · Stefanos Chaliasos, Hao Pham & the False Witness team · July 7, 2026

"The forged statement is accepted whenever the challenge is even."
CryptographyLLM auditCloudflare CIRCLPostmortem

This is the spread to sit with. zkSecurity pointed a pair of LLM configurations — a naive "just prompt it" setup versus one armed with expert-maintained audit skills, running Claude Opus 4.6/4.7 and GPT-5.3/5.4 — at Cloudflare's CIRCL, a widely-used Go cryptography library. The pipeline hardened over the project into a standing agent they call zkao, designed to keep scanning until bug discovery hits diminishing returns.

It found seven confirmed bugs, and they're not lint. A Float64 precision loss corrupts threshold-RSA polynomial evaluation; a DLEQ proof can be forged by pairing a valid proof with a different statement so it's accepted whenever the Fiat-Shamir challenge is even; a BLS aggregate-signature path is open to a rogue-key attack for lack of message-distinctness checks; an HPKE pre-shared-key validation is bypassed by a bitwise-OR switch bug. The CP-ABE access-control break was found by zkao alone, with no human in the loop.

What makes it credible as engineering rather than hype is the discipline around the model: every finding was human-validated, reduced to a minimal proof-of-concept, checked for exploitability, and responsibly disclosed through HackerOne — with commit hashes and honest notes on where the models flailed. The takeaway for a senior engineer isn't "AI replaces auditors." It's that an LLM with a good harness is now a genuine force-multiplier on the most unforgiving code there is — and that the expert-skills configuration decisively beat the naive one, which is the part worth internalizing before you point one of these at your own repo.
