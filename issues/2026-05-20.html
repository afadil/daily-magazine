№ 02 · Rose alert · Cloudflare × Stripe · FOR YOU

02  Agents can now buy domains and ship to prod.

A jointly-designed protocol from Cloudflare and Stripe lets an autonomous agent run stripe projects init, build the app, call stripe projects add cloudflare/registrar:domain, auto-provision a Cloudflare account, register a domain, and deploy to production — without a dashboard, without credential copy-paste, without a human at the keyboard. Three pieces underneath: a discovery API the agent uses to enumerate providers; Stripe as identity orchestrator (OAuth for existing users, auto-provision for new ones); and tokenized payments capped at a default $100/month per provider so a runaway agent cannot burn the card down.

Without any extra setup, agents have everything they need to deploy a new production application in one shot.

№ 05 · Newsprint · Google I/O 2026

ChromeOS folds into Aluminium OS.

The footnote that mattered yesterday wasn't the model release. It was the operating system. Google formally announced Aluminium OS, an Android-based replacement for ChromeOS aimed at the consumer-laptop market — an Android-style desktop shell, native compatibility with the Play catalog, hardware partners on stage, and a path that lets Google retire a fifteen-year-old codebase without retiring the brand.

For developers, Aluminium normalizes one thing the Chromebook strategy never quite could: "build it once for Android, ship it everywhere Google sells a screen." Compose-first apps now have a path to the laptop without a port, and the Android CLI announced alongside it gives the AI agent in your IDE a first-class CLI for semantic code analysis, Compose rendering, and automated UI testing on this new substrate.

The strategic read is messier. Aluminium consolidates Google's client surface — phone, tablet, laptop, XR glasses — at exactly the moment the rest of the stack moves toward agent-driven, headless workflows. The product question for 2027 is whether anyone is still typing on a laptop, or whether the laptop is just one of several screens an agent paints onto.

Package pruning ships in .NET 10.

.NET 10 ships package pruning: platform-provided packages are removed from dependency graphs at build time. The number Microsoft is highlighting from default-config projects is a 70% reduction in transitive vulnerability reports — not because the code changed, but because the graph the scanner walks finally matches the graph the runtime executes. № 08 · Academic · Claude Managed Agents · FOR YOU

Memory by "dreaming."

The agent runs offline against its own transcripts and crystallizes what generalizes — not a vector store, not a scratchpad, a curriculum it gave itself.

Anthropic added three features to Claude Managed Agents this week. The notable one is a memory capability they call dreaming: when an agent goes idle, it replays its own past transcripts in a background pass, distills what is reusable across sessions, and writes that back as compact, task-shaped memory. The second is self-hosted sandboxes, which finally let tool execution run inside your VPC instead of Anthropic's infrastructure — the missing piece for shops where data-residency was the blocker. The third is multiagent orchestration as a first-class primitive, with isolation and budget per child. If you build agent platforms, the takeaway is that the abstraction layer is stabilizing fast: memory, sandbox, orchestration are now features of the model, not the framework above it.

№ 10 · Botanical · Weird science

The Chinese money plant grows a Voronoi diagram.

A team studying Pilea peperomioides — the Chinese money plant — found that the coin-shaped leaves develop their internal cell pattern as a Voronoi tessellation: every cell is bounded by points equidistant from its neighbors' centers, the same geometry your network engineer uses for region partitioning and your graphics engineer uses for procedural terrain. The biology was assumed to be ad-hoc; the math turns out to be load-bearing. A small reminder that some of the data structures we charge for are rediscovered, free, in a houseplant.

№ 12 · Feature · Databricks Engineering · May 6, 2026 · Aaron Davidson · Roland Fäustlin · Zach Williams

Rethinking distributed systems for serverless performance and reliability.

Databricks' new piece is the clearest articulation in a while of why the classic Spark cluster shape — users sharing a driver, sharing executors, sharing JVMs — is the wrong abstraction for the workload it now carries. The thesis: exposing infrastructure to users is the bug. The post then walks through the three systems they replaced it with, with real numbers attached. Spark Connect splits the application from the driver over gRPC, so a runaway notebook can't take out a multi-tenant cluster; they report 99.998% success across 4.5B workloads, and 25 major Spark runtime upgrades a year with zero user action. A Serverless Gateway routes each query on three live signals — estimated query size, cluster utilization, latency profile — so a five-row exploratory query doesn't queue behind an ETL job. Adaptive autoscaling resizes both horizontally and vertically, including the trick of detecting OOM and silently relaunching the task on a larger VM. Unilever's reported result is the kind of number a postmortem rarely produces: 2–5× faster pipelines, 25% lower cost.

Exposing infrastructure directly to users creates tight coupling between applications and compute — and that coupling is what every reliability symptom rolls back to.

The lesson worth carrying over to non-Spark systems: when a multi-tenant cluster's tail-latency problem will not yield, look for what is shared that does not need to be. The fixes here are not algorithmic; they are topological. A gRPC boundary, an intelligent router, and an autoscaler that can move you vertically were each off-the-shelf primitives for years. The architectural insight was deciding that a driver running user code in-process was the assumption to give up.
